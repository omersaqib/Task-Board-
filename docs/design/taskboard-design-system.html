TaskBoard · Sprint 2 · Design system v1

The Ledger: TaskBoard's new interface

Tasks read like entries in a ruled ledger: a status mark, a title, a priority meter and a due date set in figures. Cards are kept for the two places where you write: the task composer and the sign-in forms. This page is the handoff. Its tokens and component CSS are the source the frontend implements from.

01 Foundations

Color, type, space

Every color is a token with a light and a dark value. Status and priority colors are semantic and never double as the accent. Each one also has a shape (glyph, meter bars) so state is readable without color.

04 Handoff

Handoff rules for the frontend team

The design changes how the app looks. It must not change what the E2E suite relies on.

  1. Copy Section 1 tokens into frontend/src/design/tokens.css and the Section 2 component CSS into frontend/src/design/components.css. Replace the @container rules with @media at the same widths. Delete the old ad-hoc rules in styles.css.
  2. Every accessible name, label, role, route, text and data-testid in docs/CONTRACTS.md stays identical. Decorative additions (glyph, meter, due hint, icons) are aria-hidden or separate elements outside contract nodes.
  3. [data-testid=task-priority] text stays the lower-case word; [data-testid=task-due] text stays “Due YYYY-MM-DD”; the relative hint is a sibling element.
  4. Do not add a second element with any contract name on the same page (e.g. no extra “Search” or “Log in” button).
  5. Both themes follow prefers-color-scheme. Text meets 4.5:1 in both; control borders and focus rings meet 3:1.
  6. No horizontal scroll at 375px with long unbroken titles (REG-007 must stay green).
  7. Load fonts from Google Fonts in index.html with display=swap and the fallback stacks given in the tokens.
